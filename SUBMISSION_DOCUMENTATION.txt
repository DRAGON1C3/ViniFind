ViniFind — документация к решению
ЛЦТ2026, задача «Сканер российских вин с описанием на платформе Своё Вино»

1. Назначение проекта

ViniFind — встраиваемый веб-модуль, который помогает определить российское вино по фотографии этикетки. Пользователь загружает фотографию, а система возвращает конкретный slug вина для открытия карточки в каталоге.

2. Пользовательский сценарий

1) Пользователь открывает веб-интерфейс.
2) Фотографирует этикетку или выбирает изображение из галереи.
3) Frontend отправляет изображение в API.
4) API создаёт задачу и помещает её в RabbitMQ.
5) Python ML-воркер получает задачу и выполняет visual retrieval.
6) Результат возвращается через RabbitMQ в API.
7) Пользователь получает slug и карточку найденного вина.

3. Архитектура

- Frontend: мобильный веб-интерфейс и демонстрационный mockup.
- ASP.NET Core API: приём изображений, создание задач, получение результатов.
- RabbitMQ: асинхронная очередь между API и ML-воркером.
- Python ML worker: обработка изображений и поиск кандидатов.
- SigLIP: построение визуальных embedding-векторов и поиск похожих изображений.
- PostgreSQL/pgvector: инфраструктурная основа для каталога и будущего векторного поиска.
- Docker Compose: запуск PostgreSQL и RabbitMQ локально.

4. API

Основной сценарий:

POST /api/scan
GET /api/scan/{taskId}

Endpoint для жюри:

POST /api/jury/scan

Endpoint жюри принимает multipart-файл с именем File и возвращает упрощённый JSON:

{"slug":"wine-slug"}

5. ML-часть

Для visual retrieval подготовлен индекс изображений российского винного каталога. Индекс содержит 2168 связей с товарами и 2091 уникальное изображение. Для запроса формируется список Top-5 визуальных кандидатов с оценками совпадения.

Текущая версия является рабочим baseline. На сложных фотографиях похожие бутылки могут быть перепутаны. Для дальнейшего повышения точности предусмотрены OCR/VLM для чтения текста этикетки и RapidFuzz для текстового переранжирования по названию, производителю, сорту и году урожая.

6. Запуск инфраструктуры

В корне репозитория:

docker compose up -d

RabbitMQ Management:

http://localhost:15672

После запуска инфраструктуры необходимо запустить ASP.NET Core API и Python ML worker согласно конфигурации проекта.

7. Ограничения демонстрационной версии

- Часть ML-артефактов и фотографий передаётся отдельно и не хранится в Git.
- Visual retrieval является baseline и не гарантирует правильный Top-1 для каждой фотографии.
- Для production-эксплуатации требуется постоянное хранилище задач, полноценная OCR/VLM-обработка и настройка безопасности.
